\chapter{Methodology}
This chapter details the methodology for the proposed Flow Planner framework, a novel hierarchical framework for long-horizon trajectory planning. This chapter is structured to build from foundational theory to the specific contributions of this work.

Section \ref{sec:cfm_formulation} first introduces the theoretical underpinnings of Conditional Flow Matching (CFM), a powerful, recently proposed paradigm for generative modeling. Building upon this, Section \ref{sec:planners} introduces a clever reformulation of the CFM objective, specializing this framework to the complex domains of robotic trajectory planning. This section goes over the general formulations for each planner component developed in this dissertation. Finally, Section \ref{sec:fp_framework} describes how these components are integrated into the complete hierarchical framework. 

The formulations presented herein are adapted from the convention from "An Introduction to Flow Matching and Diffusion Models" by MIT CSAIL \cite{holderriethIntroductionFlowMatching2025}, as well as the “Flow Matching Guide and Code” provided by Meta \cite{lipmanFlowMatchingGuide2024a}.


\section{Conditional Flow Matching Formulation}
\label{sec:cfm_formulation}
Recall in Section \ref{sec:fm_generative_models}, the general Flow Matching objective \ref{eq:fm_objective} is intractable because it requires access to the marginal probability path $p_t(x)$ and its corresponding vector field $u_t(x)$. Conditional Flow Matching (CFM) is a practical implementation that solves this problem by defining the probability path such that it yields a tractable target vector field. This transforms the objective into a stable and efficient regression problem. 

\subsection{CFM Training}
CFM constructs the path as a simple linear interpolation between a point sampled from a prior distribution $x_0 \sim p_0$ and a point from the data distribution $x_1 \sim p_1$. The prior is usually standard Gaussian noise $p_0(x) = \mathcal{N} (0, I)$. The point on the path at any time $t \in [0,1]$ is defined as:
\begin{equation}
	x_t=(1 - t)x_0+ tx_1.
\end{equation}
This specific construction is a type of Gaussian probability path referred to as the CondOT (Conditional Optimal Transport) path \cite{lipmanFlowMatchingGuide2024a}. The ground truth vector field requiring to move a particle along this straight path is constant at all times, and it is simply the vector connecting the two endpoints:
\begin{equation}
	u_t(x_t) = x_1-x_0.
\end{equation}
This replaces the intractable integral of the general formulation with a simple difference of two vectors, which are readily available during training.
By substituting this simplified target vector field into the general objective in \ref{eq:fm_objective}, one arrives at the final CFM loss function. The goal is to train a neural network $ v_{\theta} (x_t, t, c)$ to predict the target vector $(x_1 - x_0) $ given the interpolated point $x_t$ and time $t$, and any optional conditioning variables $c$. This objective is a straightforward L2 regression loss:
\begin{equation}
	L_{CFM}(\theta)=E_{t,p_0(x_0),p_1(x_1)}[\|v_\theta((1-t)x_0 + tx_1, t, c)-(x_1-x_0)\|^2].
\end{equation}
A single training step is summarized in Algorithm \ref{alg:cfm_training}


\begin{algorithm}
\caption{CFM Training}\label{alg:cfm_training}
\begin{algorithmic}[1]
\Require Dataset of samples $\mathbf{x}_1 \sim p_{\text{data}}$, neural network $v_\theta$, prior distribution $p_0$ (e.g.\ $\mathcal{N}(0, I)$)
\For{each training step}
    \State $\mathbf{x}_1 \sim p_{\text{data}}$ \Comment{Sample a data point}
    \State $\mathbf{x}_0 \sim p_{0}$ \Comment{Sample a noise vector}
    \State $t \sim \text{Unif}[0,1]$ \Comment{Sample a random time}
    \State $\mathbf{x}_t \gets (1-t)\mathbf{x}_0 + t\mathbf{x}_1$ \Comment{Compute interpolated point}
    \State $\mathbf{u} \gets \mathbf{x}_1 - \mathbf{x}_0$ \Comment{Compute target vector}
    \State $\mathcal{L}(\theta) \gets \|v_\theta(\mathbf{x}_t, t, c) - \mathbf{u}\|^2$ \Comment{Compute the loss}
    \State $\theta \gets \theta - \eta \nabla_\theta \mathcal{L}(\theta)$ \Comment{Gradient descent update}
\EndFor
\end{algorithmic}
\end{algorithm}
This is a simulation-free objective, hence it only requires sampling one data point, one noise vector, and a time to perform a standard regression update. It avoids the costly ODE solves of traditional CNF training and forms the foundational recipe for the specific planners detailed in the following sections. While the CondOT path is a common choice, the implementation in this dissertation utilizes a more general affine probability path. This formulation, known as the "Affine Conditional Flow Matching" variant in Albergo et al. [cite here], defines an exact conditional distribution over the interpolants instead of a single deterministic interpolation. This preserves key probabilistic properties, leading to more stable training dynamics and a closer theoretical alignment with Schrödinger Bridge formulations \cite{tongSimulationfreeSchrodingerBridges2024}. The detailed derivation of the base CFM objective is provided in Appendix \ref{app:cfm_derivation}.

\subsection{CFM Inference}
While the training process for CFM is simulation-free, inference requires simulating the learned dynamics. The goal of inference is to generate a new sample  $x_1$  that approximates a draw from the true distribution by solving an Ordinary Differential Equation (ODE). The trained neural network $v_\theta(x_t, t, c)$ now serves as an approximation of the true (but intractable) marginal vector field that transforms noise into data. Generation begins by sampling an initial point from the prior distribution $\mathbf{x}_0 \sim p_0(\mathbf{x})$. This point is then evolved from $t=0$ to $t=1$ by solving the following ODE:
\begin{equation}
	\frac{d\mathbf{x}t}{dt} \;=\; v_\theta(\mathbf{x}_t, t, c).
\end{equation}
The solution to this ODE, $x_1$, is the final generated sample. Since this ODE rarely has an analytical solution, it must be solved numerically. A common choice is the simple \textbf{Euler method}, detailed in Algorithm \ref{alg:euler}.
\begin{algorithm}
	\caption{Euler Method}\label{alg:euler}
	\begin{algorithmic}[1]
	\Require Neural network $v_\theta$, prior distribution $p_0$, condition $c$, number of steps $N$
	\State $\mathbf{x}_0 \sim p_0(\mathbf{x})$ \Comment{Sample an initial point}
	\State $\Delta t \gets 1/N$
		\For{$i = 0$ to $N-1$}
    		\State $t \gets i \cdot \Delta t$
		    \State $\mathbf{x}_{t+\Delta t} \gets \mathbf{x}_t + v_\theta(\mathbf{x}_t, t, c) \cdot \Delta t$ \Comment{Take a step along vector field}
		\EndFor
	\State \Return $\mathbf{x}_1$
\end{algorithmic}
\end{algorithm}

 It is worth noting that for Stochastic Differential Equations (SDEs), the corresponding simple solver is the Euler-Maruyama method. For the experiments in this dissertation, a more advanced solver, \textbf{the midpoint method} (a 2nd-order Runge-Kutta scheme) is employed \cite{lipmanFlowMatchingGuide2024a}. This choice offers a better trade-off between computational cost and numerical stability, leading to higher-quality samples compared to the basic Euler method.

\section{Planners Formulation}
\label{sec:planners}
The general Conditional Flow Matching (CFM) objective from Section \ref{sec:cfm_formulation} provides a simulation-free training recipe. While this framework has been successfully specialized for a range of generative modeling tasks, particularly in domains such as image and video synthesis, its application to trajectory planning remains largely unexplored.

This section details the novel specialization of the CFM framework for trajectory planning. To present the methodology in a unified manner, this section first presents a generalized planner formulation and then details how this single framework is instantiated for three different planners: Joint Planner (JP), Waypoint Planner (WP), and Action Planner (AP).  Note the distinction between the overall task horizon $T$, which can be arbitrarily long, and the fixed planning horizon of the model $H$, which is a number of steps the generative model is trained to predict. This distinction is key to how the framework manages long-horizon problems.
\subsection{Generalized Planner Formulation}
Let $\tau$ represent a generic trajectory data sample. This sample can be a state-action sequence, a state-only sequence, or an action-only sequence over the planning horizon $H$ and let $c$ be a set of conditioning variables. The goal is to learn a conditional distribution $p(\tau \mid c)$ by training a neural network $v_{\theta}(\tau_t, t, c)$. 
The generalized CFM objective for any planner is given by:
\begin{equation}
	\mathcal{L}(\theta) = \mathbb{E}_{t, \tau, \tau_{noise}} 
\|v_{\theta}(\tau_t, t, c) - (\tau-\tau_{noise})\|,
\end{equation}
where $\tau$ is a ground-truth trajectory from the dataset, $\tau_{noise} \sim \mathcal{N}(0,I)$, and
\begin{equation}
	\tau_{t} = (1-t) \tau_{\text{noise}} + t\tau.
\end{equation}


\subsection{Planner Specializations}
The three planners implemented below are specific instances of the above generalized formulation, differing only in their choice of trajectory data $\tau$ and conditioning variables $c$. 

\subsubsection{\textbf{Joint State-Action Planner (JP)}}
The Joint Planner is designed to generate a complete, long-horizon strategy that includes both states and actions. It learns the conditional distribution over entire state-action trajectories $p(\tau \mid c)$, where $c = (s_{start}, s_{goal})$. A JP outputs a trajectory designed over the planning horizon $H$:
\begin{equation}
	\tau = (s_0, a_0, ..., s_H, a_H).	
\end{equation}
This formulation is inspired by the inpainting-based planning approach of Janner et al, who demonstrated the feasibility of generating trajectories within a diffusion model framework \cite{jannerPlanningDiffusionFlexible2022}. However, whereas their method relied on a separate guidance function $\mathcal{J}_\phi $ to steer the sampling process, my CFM-based implementation models the conditional distribution directly. While this end-to-end approach is theoretically powerful (and intuitive) for open-loop planning, modeling the full joint state-action space over a long horizon is often practically infeasible. The subsequent planners are designed to mitigate this by decoupling the problem.

\subsubsection{\textbf{State-Only Waypoint Planner (WP)}}
I proceed to decouple the high-level pathfinding from the low-level control. The Waypoint Planner generates a long-horizon strategic plan consisting only of states, which serve as a sequence of waypoints for a low-level controller, also defined over the planning horizon $H$:
\begin{equation}
	\tau_s = (s_0, .. s_H).
\end{equation}
The Waypoint Planner learns the conditional distribution over state-only trajectories, $p(\tau_s \mid c)$, where the conditioning  $ c = (s_{start}, s_{goal})$ remains the same.

\subsubsection{\textbf{Action Planner (AP)}}
Inspired by the work of Chi et al.’s on Diffusion policy, the Action Planner is designed to be a reactive, low-level policy \cite{chiDiffusionPolicyVisuomotor2023}. Its role is to generate a short-horizon sequence of actions that guides the agent from its current state to a nearby waypoint, typically provided by a high-level planner like the WP. 
\begin{figure}[H]
  \centering
  \includegraphics[width=1.0\textwidth]{action_planner}
  \caption{Action Planner Visualized}
  \label{fig:ap}
\end{figure}
It learns the conditional action distribution $p (\tau_{a}\mid c)$, where the conditioning is $c = (s_{current}, s_{waypoint})$. Note the action sequence is defined over a short action horizon $H_a$ , where $H_a \ll H$.
\begin{equation}
	\tau_{a} = (a_0, \dots, a_{H_{a}}).
\end{equation}

\section{Flow Planner Framework}
\label{sec:fp_framework}
The individual planners in Section \ref{sec:planners} are composed into a hierarchical framework that tackles long-horizon tasks by decoupling high-level strategic reasoning from low-level reactive control. This section details the framework’s operational flow and motivates the key design choices. The architecture pairs a state-only Waypoint Planner (WP) at the high level with an Action Planner (AP) at the low level, executed within a Model Predictive Control (MPC) loop. MPC follows a receding-horizon scheme: at each step a finite-horizon open-loop plan is computed; only its first action is applied, after which the horizon is shifted and the optimization re-solved \cite{mayneConstrainedModelPredictive2000}.


\subsection{Hierarchical Planning Process}

The planning process unfolds in two distinct stages: an initial strategic planning phase and a continuous, reactive control loop.
\begin{enumerate}
	\item \textbf{Global Plan Generation}: At the beginning of a planning cycle, the Waypoint Planner (WP) is invoked to generate a strategic plan, $\tau_s=(s_0,\dots,s_H)$, over its fixed planning horizon $H$. The conditioning signal for this planner, $c = (s_{start}, s_{goal})$ can be formulated in two ways, each with distinct purpose:
	\begin{itemize}
		\item \textbf{Final Goal Conditioning}: The planner can be conditioned on the final goal of the entire task horizon, where $s_{goal} = s_T$. This provides the model with the ultimate objective, encouraging it to generate a plan that is globally directed towards the final destination.
		\item \textbf{Waypoint Goal Conditioning}: Alternatively, the planner can be conditioned on an intermediate goal at the end of its planning window, $s_{goal} = s_H$. In this receding-horizon approach, the planner solves a shorter, more immediate problem. For tasks whose total duration exceeds the planning horizon ($T \gg H)$, the WP can be invoked in a low-frequency receding-horizon manner as well to generate the next segment of the plan once the current one is near completion.
	\end{itemize}

	\item \textbf{Reactive MPC Loop}: The system then enters a high-frequency MPC loop to execute the plan:
		\begin{enumerate}	
			\item The agent's current state, $s_{current}$, is observed.
			\item The next immediate waypoint, $s_{waypoint}$, is selected from the global plan $\tau_s$.
			\item The  AP is conditioned on both the current state and the target waypoint, $c=(s_{current},s_{waypoint})$ and generates a short-horizon action sequence, $\tau_{a}=(a_0,\ldots,a_{T_{a}})$.
			\item The first action $a_0$ from this sequence is executed in the environment.
			\item The process repeats, with the agent progressing through the waypoints of the global plan.
	\end{enumerate}
\end{enumerate}
The full procedure is detailed in Algorithm \ref{alg:hierarchical}.
\begin{algorithm}
\caption{Hierarchical Planning}\label{alg:hierarchical}
\begin{algorithmic}[1]
\Require Trained Waypoint Planner $v_{\theta}^{WP}$, Trained Action Planner $v_{\theta}^{AP}$, initial state $\mathbf{s}_{\text{start}}$, goal state $\mathbf{s}_{\text{goal}}$
\Ensure Action sequence leading to $\mathbf{s}_{\text{goal}}$

\State $\tau_s \gets \text{sample}\!\left(v_{\theta}^{WP} \;\mid\; \mathbf{s}_{\text{start}}, \mathbf{s}_{\text{goal}}\right)$ \Comment{Generate high-level plan}
\State $i \gets 1$
\State $\mathbf{s}_{\text{current}} \gets \mathbf{s}_{\text{start}}$

\While{not terminated}
    \State $\mathbf{s}_{\text{waypoint}} \gets \tau_s[i]$
    \State $\mathbf{A}_{\text{seq}} \gets \text{sample}\!\left(v_{\theta}^{AP} \;\mid\; \mathbf{s}_{\text{current}}, \mathbf{s}_{\text{waypoint}}\right)$
    \State $a_0 \gets \mathbf{A}_{\text{seq}}[0]$
    \State $\mathbf{s}_{\text{next}} \gets \text{Execute}(a_0)$ \Comment{Execute action and observe next state}
    \State $\mathbf{s}_{\text{current}} \gets \mathbf{s}_{\text{next}}$
    \If{$\text{distance}(\mathbf{s}_{\text{current}}, \mathbf{s}_{\text{waypoint}}) < \text{threshold}$} \Comment{Check if waypoint was reached}
        \State $i \gets i+1$ 
    \EndIf
\EndWhile

\end{algorithmic}
\end{algorithm}
